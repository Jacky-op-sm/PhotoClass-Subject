# Firebase setup

1. Open the Firebase console and create a dedicated project for PhotoClass Subject. Use an available project ID, such as the suggested `photoclass-subject` with a unique suffix. [Firebase console](https://console.firebase.google.com/)
2. Upgrade this project to the Blaze billing plan and link its billing account. In Cloud Billing → Budgets & alerts, create a monthly budget scoped to this project, for example US$1, and enable email alerts. A budget sends notifications. Charges can continue beyond its amount. [Firebase billing plans](https://firebase.google.com/docs/projects/billing/firebase-pricing-plans)
3. Under Firestore Database, create the default database in **Standard** edition and **production mode**. Pick a location such as Iowa (`us-central1`). In Indexes → Single field, exempt the map field `progress` in the `subject_profiles` collection group from automatic indexing. The site gets this document by its exact path. The exemption also covers the map’s descendants. [Index exemptions](https://firebase.google.com/docs/firestore/query-data/index-overview#single-field_index_exemptions)
4. Under Storage, create the default bucket with Standard storage in **Iowa (`us-central1`), South Carolina (`us-east1`), or Oregon (`us-west1`)**. Those three regions share the Cloud Storage Always Free allowance. New default buckets have names ending in `.firebasestorage.app` and require Blaze. [Default bucket requirements](https://firebase.google.com/docs/storage/faqs-storage-changes-announced-sept-2024)
5. Open **Sync settings** on the study site and choose **Generate**. Keep the entire generated value in your password manager. In **Firestore Database → Rules**, paste the Firestore template and replace its `__SYNC_CODE__` placeholders with that value directly in the console, then publish. Under **Storage → Rules**, repeat using the Storage template. [Firestore template](firestore.rules.template) · [Storage template](storage.rules.template)
6. In **Project settings → General → Your apps**, register a web app, choose the Config snippet and copy its public fields, including the actual bucket name, into `assets/js/firebase-config.js`. Preserve the `window.PHOTOCLASS_FIREBASE_CONFIG` assignment. Save the public web configuration and reload the local study site. [Web setup](https://firebase.google.com/docs/web/setup)
7. Enter your saved code in **Sync settings** on each browser and local origin you use. Wait for **Synced**, then add a subject and verify that it appears in another browser. Upload a small test JPEG, check both derivatives on the second device and delete it. Disconnecting a browser keeps its local study progress. Treat exported progress files and photo URLs as private backups because object paths contain the access code.

## Free usage checked on November 23, 2026

Cloud Storage’s eligible regions share 5 GB-months of Standard storage, 5,000 Class A operations and 50,000 Class B operations per month. The 100 GB monthly outbound allowance from North America excludes China and Australia. Photo downloads to China may incur network charges. [Cloud Storage pricing](https://cloud.google.com/storage/pricing#cloud-storage-always-free)

The default Standard Firestore database has free quotas of 1 GiB stored, 50,000 document reads per day, 20,000 writes and 20,000 deletes per day, and 10 GiB of outbound transfer per month. A single document supports up to 1 MiB. The site logs a size warning when the progress JSON exceeds 700 KiB. [Firestore usage and limits](https://firebase.google.com/docs/firestore/quotas)
